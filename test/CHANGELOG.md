## v1.0 details
**Fixed:** C1 (no saving after failed load, blocking Retry screen, status no longer forced green), C2 (wallets/people/cards/monthly/categories now per-row; no client whole-table writes), C3 (allow-list check on every function + doGet; ALLOWALL removed), H2 (atomic `appendItems`; transfer halves deleted together via `deleteByField`; transfer edit blocked).
**Added:** `LEDGER_VERSION` (shown top-right as vX.Y), Drive backups (manual, before import, nightly 2 AM, keeps 30), guarded import (`confirmReplace`, backup first, empty can't wipe data, write-then-trim), `withLock_` null-safe lock, input validation, grid auto-grow on append.
**Still true (Phase 2):** a failed single add still shows the row until Refresh (optimistic UI); `updateItem`/`deleteItem` returning false is not yet surfaced; category tabs start empty on a fresh Sheet; `onOpen` is still slow.
**Removed:** client `setData`/`getData`, old data-shape migration in `loadAll`.

## v2.0 details
**Fixed:** C4 (formats set BEFORE every write, whole-column formats, grid auto-grows, `repairFormats_` fixes cells already auto-parsed; dates read in the SPREADSHEET timezone, time from displayed text; numbers must be finite, text capped so `=`/`+` notes stay text), H1 (failed add/edit/delete now rolls the screen back; rows show faded + "N saving…" while pending; server replies `{ok:false,reason}` and "not_found" shows "Entry nahi mili — Refresh karo"), H3 (default categories seeded on the server; client fallback removed), H4 (import success only when the save really succeeded; screen resynced on failure), H5 (capacity guard), H6 (no setup on open; tabs created lazily; no autoResize; fixed widths).
**Added:** idempotent `appendItem`/`appendItems` (same id twice => one row, `duplicate:true`), `seedTestRows_(n)` / `clearTestRows_()` (need Script Property `ALLOW_TEST_SEED=true`, COPY only), amount columns use `General` format (no more `100.`).
**API change:** every write returns `{ok:true|false, ...}` instead of true/false.
**Still open (Phase 3+):** UTC "today" bug (M1), date validation (M2), auto-refresh across devices (M4), HTML escaping of dates/ids (M5), tab naming/archive/delete person-card-category (M6/M7), offline persistence (Phase 5). Re-adds after a *timeout* are safe (same id), but there is no automatic retry yet.

## v3.0 details
**Dates / numbers (M1, M2):** `todayStr()` and every current month/year use LOCAL date parts (no more UTC "yesterday" at 1:30 AM IST). Strict date validation on client AND server (real calendar date, 2000–2100; `31-02-2026` is blocked with a message). Times must be `HH:mm`. Money shows paise only when present (`₹12.50`), sums are rounded to 2 decimals (no `0.1+0.2` noise), chart axis shows `₹850` / `₹1.5k`. Rows read from the Sheet are validated; broken ones (bad date, bad id, bad type, non-numeric amount) are parked in a red "Needs attention" box on the Dashboard instead of crashing the app.
**Auto refresh (M4):** server `DATA_VERSION` counter bumped (inside the lock) by every real write; every write reply carries `v`. The app polls `getDataVersion()` every 45 s while the tab is visible and reloads silently if another device wrote. It never refreshes over a half-typed form, an open edit, or while saves are pending; own writes don't trigger a self-refresh. Toast: "Doosre device se update aaya ✓".
**Unsaved-save retry (M3, in-memory only):** an INTERNET failure no longer rolls the row back: it stays on screen tinted amber, a "⚠ N unsaved — Retry now" button appears, and the queue flushes automatically when the connection returns / on the next poll / on click. Queue is ordered, coalesced (edit of a never-saved row folds into its add; delete cancels it) and idempotent (same id twice => one row). A real server rejection still rolls back. Leaving the page with unsaved entries asks for confirmation; Refresh offers to flush first. Real offline persistence is Phase 5.
**localStorage probe:** the footer shows `offline storage in this view: available | blocked` (also in the browser console). Please tell me what it says in your Apps Script web app AND in the sidebar/dialog: it decides how Phase 5 stores the offline outbox.
**Security (M5):** server rejects ids that are not `[A-Za-z0-9_-]{1,40}` (deviation from the suggested `[a-z0-9]{6,40}`: still blocks every injection character but never rejects a legitimate or hand-typed id). Client re-validates every id/date/time/type read from the Sheet and escapes all dynamic values with `h()`.
**Data model (M6, M7):** tab "Monthly Summary" is now "Monthly Manual Base" (renamed by Setup/Repair; the old name is still found until then). New `Archived` column at the END of Wallets, People, Credit Cards: Archive/Restore buttons, "Archived dikhao" checkbox, archived items vanish from dropdowns but their balances/history still count. Delete person / card only when they have no entries (otherwise it points you to Archive). Wallet delete tells you how many entries in other tabs are linked ("Not linked", not deleted). Category manager (✕) on Expenses and Daily; existing entries keep their text; last category is protected. Dead code removed, beige leftovers recoloured to the indigo theme.
**Export / import:** Excel now carries IDs, TransferID, Archived and separate People / Cards / Category sheets so a round trip loses nothing; import skips (after asking) rows that are invalid instead of failing the whole file. New "📄 CSV" button (the original app's snapshot, saved as a file; formula-injection safe). Drive push stays removed.
**Not done (later phases):** true offline persistence + background sync (Phase 5), paging/search/10k-row speed (Phase 4).
**Bug found & fixed while testing:** Setup/Repair did not rename the legacy Monthly tab; a transient-error check mis-classified empty error messages as permanent.

## v5.0 details (desktop-first PWA)
**New file system:** `index.html`, `sw.js`, `manifest.json` in the root; `css/styles.css`; `icons/` (3 SVG + 4 PNG fallbacks, drawn by `tools/make_icons.py`); `_headers` + `.nojekyll` for hosting; `tools/build.js` (generates index.html + css from `src/Ledger.html`, stamps a content hash into `sw.js`), `tools/dist.js` (deployable folder only); `test/` (this changelog + all tests); `package.json` (`npm test`, `build`, `dist`, `serve`).
**One source of truth:** `src/Ledger.html` runs unchanged inside Apps Script (Google login) AND as the hosted PWA (token). `IN_APPS_SCRIPT` picks the transport; a test proves index.html's script is byte-identical to the Sheet version's.
**Secure API (`doPost` in Code.gs):** disabled until a token exists; only the SHA-256 HASH of the token is stored; constant-time compare; action allow-list (setBulkData / setData / repair / backup / seed are NOT reachable); 120 requests/min; 10 wrong tokens = 10-minute lockout; kill switch + token rotation + lockout reset in the Ledger menu; "Audit Log" tab records writes and failures only (never ledger data, trimmed to ~2000 rows); all Phase 1-3 validation still applies; API access can never leak into a normal call (flag reset in `finally`).
**PWA client:** pair screen (URL must be `https://script.google.com/.../exec`: the token is never sent anywhere else), token stored AES-GCM-encrypted under a PBKDF2(150k) PIN key, 5 wrong PINs = 30 s delay, auto-lock after 15 idle minutes + Lock button (clears the screen, wipes token/key from memory, sends nothing while locked), rotated/revoked token => stale pairing forgotten and re-pair requested, encrypted offline snapshot => opens read-only with an amber banner when the Sheet is unreachable and reconnects automatically, install button, "Naya version available — Reload" (never reloads over unsaved entries), `?tab=` deep links from desktop shortcuts, Alt+1..7 tab keys.
**Service worker:** caches only the shell + public CDN assets; never POST, never script.google.com, never ledger data; network-first navigation with 3 s timeout (patchy connections); first install does not reload the page; `skipWaiting` only when the user clicks Reload.
**Desktop first / mobile second:** wide layouts >=1280px and >=1700px, print stylesheet, focus rings; mobile: safe-area insets, 16px inputs (no iOS zoom), 40px tap targets, hover-less devices. **Sheet version mobile meta:** viewport-fit=cover, theme-color, apple/mobile web-app meta, format-detection in `Ledger.html` AND added by `doGet`; optional favicon via Script Property `PWA_ICON_URL`.
**Tests (101):** static 16 (manifest, icons, SW, build sync, no secrets, dist), backend 35 (+13 API), client 18, Sheet-mode e2e 17, PWA e2e 16 (pairing, wrong URL/token/PIN, encryption at rest, lock/idle/lockout, kill switch, rotation, offline snapshot, tamper, deep link).
**Not verified here:** real Google endpoints (CORS / redirect behaviour of Apps Script POST, real service-worker install, real Chrome/Edge install prompt, iOS). The code follows the documented pattern (text/plain POST, redirect: follow); please run the v5.0 checklist on your machine.
**Not done:** Phase 4 (paging/search/10k rows), persistent offline write outbox (`prompts/phase5b_offline_outbox.md`).
